# F1 Strategy AI Component

This module contains the real-time AI/ML decision engine for recommending F1 racing strategy (OVERTAKE, HOLD, RECOVER) based on telemetry and race context. 

## Overview
The ML objective is to consider finite energy availability and race context to recommend the optimal deployment strategy. This module is entirely self-contained within the `ai/` directory and does NOT modify the backend, frontend, or grid components.

## Data Pipeline
Raw telemetry is sourced dynamically using the **FastF1** package. The pipeline follows:
FastF1 -> F1 Session Data -> Telemetry extraction -> Data cleaning -> Feature engineering -> Domain-heuristic labels -> Training dataset -> ML classifier -> OVERTAKE / HOLD / RECOVER

**IMPORTANT NOTE ON DATA/LABELS**: 
- **Raw Data**: We use real, publicly accessible telemetry data obtained through `FastF1`.
- **Labels**: FastF1 **does not** provide ground-truth strategy labels or proprietary battery telemetry. The `OVERTAKE`, `HOLD`, and `RECOVER` labels are synthetically generated using documented domain heuristics based on the engineered features. The model learns these heuristics to provide a multi-variate, continuous decision boundary, but it **did not learn directly from real driver overtake decisions**.
- **Features**: Since actual battery level is proprietary and not public, `ers_level`, `energy_deployment`, and `energy_recovery` are defensible, synthetic proxies computed over lap progress and throttle/brake profiles. Gaps (`gap_ahead`, `closing_speed`) are also synthetic approximations to provide the necessary temporal dynamics for the hackathon pipeline.

## Features
- **Direct FastF1 Features**: `speed`, `throttle`, `brake`, `gear`
- **Proxy/Derived Features**: `ers_level`, `energy_deployment`, `energy_recovery`, `gap_ahead`, `gap_behind`, `closing_speed`, `lap`, `energy_per_remaining_lap`, `attack_opportunity_score`, `recovery_opportunity_score`, `drs_available` (derived from `DRS` channel).
- **Optional Grid Feature**: `grid_energy_condition` (a synthetic external constraint signal, randomized for proof-of-concept).

## Model
The project uses a **RandomForestClassifier** (falling back from XGBoost due to OS-level `libomp` requirements for XGBoost on OSX). 
It is trained on the processed telemetry from multiple sessions (chronologically split).

## Running the Pipeline

### 1. Setup Environment
```bash
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
```

### 2. Train the Model
This will download FastF1 data (if not cached in `ai/data/cache/`), process it, generate labels, and train the model.
```bash
python -m src.train
```

### 3. Evaluate the Model
Evaluates the saved model against a held-out test session (e.g. 2023 Zandvoort).
```bash
python -m src.evaluate
```

### 4. Inference
The backend developer can use the ML component via the `predict()` function:

```python
from src.predict import predict

race_state = {
    "speed": 310,
    "throttle": 0.98,
    "brake": 0.0,
    "gear": 8,
    "drs_available": 1,
    "ers_level": 72,
    "gap_ahead": 0.42,
    "closing_speed": 5.0,
    # ... other features
}

result = predict(race_state)
print(result)
# Output: 
# {
#   "action": "OVERTAKE", 
#   "confidence": 0.87, 
#   "expected_energy_cost": 0.35, 
#   "reason": "Overtake recommended: gap ahead is 0.42s and energy is sufficient."
# }
```

## Explainability
The `src/explain.py` file provides natural language explanations. It defaults to SHAP explanations if `shap` is configured for the active model type, or falls back to standard feature importances, outputting human-readable text like: `"OVERTAKE recommended. Key factors (Feature Importance): ers_level, attack_opportunity_score."`

## Baseline Comparison
The `src/baseline.py` file contains a deterministic, rule-based strategy baseline (`predict_baseline()`). This takes the exact same `race_state` payload and can be used by the backend simulator to compare ML performance vs. naive rules.

## Limitations
1. **Synthetic Labels**: As mentioned, labels are generated by heuristics, not ground truth driver decisions.
2. **Derived/Proxy Features**: ERS and highly accurate gap calculations are proxied due to FastF1 constraints.
3. **Absence of Proprietary Data**: No live battery, tire degradation, or exact aerodynamic wake models are available.
